# Backend Application Integration

This phase exposes the existing M1 -> M8 orchestrator through one FastAPI endpoint:

`POST /api/assistant`

## Request

```json
{
  "content": "Mujhe kal college jana hai.",
  "current_datetime": "2026-09-15T10:00:00+05:30"
}
```

`content` is required, non-empty, and limited to 10,000 characters. `current_datetime`
must be timezone-aware. Extra request fields are rejected.

The client cannot provide `request_id`; the API creates one and passes it to the existing
orchestrator. No second request ID is generated by the orchestrator layer itself.

## Response

The response contains:

- `request_id`
- `status`
- `current_stage`
- `pipeline` — the existing `PipelineResult` serialized as JSON
- `errors`

Pipeline failures are represented as safe structured results. Unexpected application errors
are handled by the existing FastAPI exception handling without exposing stack traces or paths.

## Integration boundary

The route calls the existing `Orchestrator` and does not duplicate M1-M8 business logic.
Modules 9-15 are not newly integrated by this phase. `app/main.py` is changed only to register
the assistant router.

No LLM, database, n8n, Gmail, Calendar, browser automation, external HTTP service, shell,
`eval`, `exec`, credentials, or broad CORS policy is added.

## Testing

Run:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

The backend integration test file contains 25 tests covering request validation, safe errors,
request ID propagation, explicit datetime handling, orchestrator success/failure, regression of
the Module 1 API, deterministic mocked behavior, malformed JSON, and network-call protection.

This layer is not claimed to be production-ready.
